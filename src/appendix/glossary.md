# 用語集

本文で定義した用語を、参照用にまとめる。
意味と使い方は初出の章で説明しているため、ここでは短い定義を示す。

## スケジューリング

- **スケジューラ（scheduler）**：実行可能なタスクに CPU をどう割り当てるかを決める仕組み、またはその実装。
  本書では、Linux の標準スケジューラと自作の BPF スケジューラを文脈に応じて区別する。
- **fair class**：通常の Linux タスクを公平に扱う、標準のスケジューリングクラス。
  本編では、自作の `sched_ext` スケジューラと比較する基準にする。
- **タスク**：カーネルがスケジューリングする実行単位。
  本編では、ユーザ空間から見た説明で「プロセス」と書く場合もある。
- **runnable**：CPU を得れば命令を実行できる、実行可能な状態。
- **wakeup**：I/O やタイマーなどの待ち状態にあったタスクが、再び実行可能になる状態変化。
- **タイムスライス**：タスクが CPU 上で連続して実行するために割り当てられる時間。
- **コンテキストスイッチ**：CPU 上で実行するタスクを、別のタスクへ切り替えること。
- **CPU-bound**：実行時間の多くを CPU での計算に使う workload。
- **hog**：本編で CPU を使い続ける負荷タスクに付けた呼び名。
  負荷生成器の `cpu-hog` を二つ起動し、hog A と hog B と呼ぶ。
- **sleep**：負荷生成器のタスク。
  毎回、指定した時間だけ眠り、戻るまでの経過時間と指定時間からの遅れを記録する。
- **periodic**：負荷生成器の周期タスク。
  予定時刻ごとに処理を再開し、その時刻からの遅れを記録する。
- **idle**：CPU に実行するタスクがなく、空いている状態。
- **プリエンプション**：実行中のタスクに、スライスの終了を待たずに CPU を譲らせること。
- **deadline miss**：予定時刻からの遅れが、実験で決めた許容値を超えること。
- **CPU affinity**：タスクが実行できる CPU を制限する設定。
  本編では `taskset` で指定する。

## `sched_ext`

- **`sched_ext`**：BPF プログラムで CPU のスケジューリング方針を実装し、実行時にロードできる、Linux の拡張可能なスケジューリングクラス。
- **`sched_ext_ops`**：BPF スケジューラの callback と設定をまとめ、カーネルへ渡す構造体。
- **DSQ（dispatch queue）**：`sched_ext` がタスクを CPU へ渡すために使う待ち行列。
- **ローカル DSQ**：各 CPU が持つ DSQ。
  CPU は、最終的に自分のローカル DSQ からタスクを取り出して実行する。
- **グローバル DSQ**：カーネルが用意する、CPU 間で共有される DSQ。
- **独自 DSQ**：BPF スケジューラが作成して管理する DSQ。
- **`SCHED_EXT`**：タスクが `sched_ext` の対象になるために選べるスケジューリング方針。
- **partial switching**：`SCX_OPS_SWITCH_PARTIAL` を使い、明示的に `SCHED_EXT` を選んだタスクだけを BPF スケジューラの対象にする使い方。
- **watchdog（stall detection）**：BPF スケジューラが実行可能なタスクを長時間進められないなどの異常を検出し、そのスケジューラを停止して標準のスケジューリングへ戻す仕組み。
- **SysRq-S**：動作中の `sched_ext` BPF スケジューラを停止し、標準のスケジューリングへ戻すための SysRq 操作。

## BPF と loader

- **BPF**：カーネル内の決められた実行点で動かせる、ロード時に検証されるプログラムの仕組み。
- **BPF verifier**：BPF プログラムをカーネルへロードする前に、許されない動作などがないか検査する仕組み。
- **BTF**：カーネルや BPF プログラムの型情報を表現する仕組み。
  本編では、BPF 側からカーネルの型を扱うために利用する。
- **loader**：BPF object を開き、設定値を与えてカーネルへ load、attach するユーザ空間プログラム。
  本編では Rust で実装している。
- **rodata**：BPF object の読み取り専用データ領域。
  本編では、loader が load 前に `slice_ns` などの初期値を設定するために使う。
- **`const volatile`**：BPF のグローバル設定値でよく使われる宣言。
  本編では、BPF 側では読み取り専用として使い、loader が load 前に初期値を与えるための定型的な書き方として扱う。
- **`uei_report`**：スケジューラの exit 情報を、loader 側で整形して表示するための補助。

## 観測

- **p50、p95、p99**：遅延を小さい順に並べたときの、50、95、99 パーセンタイル。
- **tail latency**：遅延分布の上位側にある遅い部分。
  p95、p99、p99.9 などの高いパーセンタイルで観測することが多い。
- **throughput**：単位時間あたりに完了した仕事量。
  本編の遅延と切り替え回数だけでは判断できない。
- **Perfetto trace**：イベントを時系列で可視化できる trace 形式。
  発展編では、`scxtop` の出力先として扱う。
- **NUMA**：CPU とメモリの距離が一様ではないハードウェア構成。
  実機で locality を評価するときに重要になる。
