# CPU ごとの DSQ

本編の共有 DSQ は、どの CPU も同じキューからタスクを取れる。
仕事を空いた CPU へ渡しやすい一方で、タスクが前回と異なる CPU で実行される機会も増える。
移った先の CPU では、温まったキャッシュを再利用できない場合がある。
「仕事の分散」と「キャッシュの再利用」は、キューの配置をどう選ぶかで引き受ける側が変わるトレードオフである。

CPU ごとの DSQ を使う実験では、タイムスライスを固定し、キューの配置だけを変える。
スライスとキューの両方を同時に変えると、観測値の変化をどちらに帰属させるか分からなくなるためである。
比較する値は CPU migration 数、各タスクの実行時間、全体の処理量である。

4 vCPUの VM で CPU-bound worker を複数起動し、次の二条件を比べる。

1. 一つの共有 DSQ から空いた CPU が取る
2. `select_cpu` が選んだ CPU の DSQ へ enqueue する

VM の仮想 CPU とホスト scheduler が結果へ影響するため、絶対値を別のマシンと比較しない。
同じ VM 内でキュー配置だけを変えた差として読む。
