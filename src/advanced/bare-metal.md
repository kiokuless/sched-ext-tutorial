# 実機で評価する

本編の VM 実験では、同じ負荷でスライスを変え、観測値がどう動くかを比べた。
絶対値は環境に依存する。
VM 上の4 vCPU は物理 CPU コアそのものではなく、ホスト scheduler が割り当てる実行単位である。
ホスト側の実行待ちも測定へ混ざるため、VM で得た遅延や throughput をそのまま実機の性能とは見なせない。
キャッシュの共有関係、NUMA、SMT、CPU 周波数や電力の影響を調べるには、実際のハードウェア構成に対応した条件が必要になる。

これらを評価する場合は、再起動可能な Linux 実機を使う。
その場合も、次の条件を記録する。

- CPU とメモリの構成
- kernel、firmware、scx の版
- CPU governor と SMT の状態
- バックグラウンドサービス
- workload の CPU affinity
- warm-up、試行時間、反復回数
