# Rust で方針を書く

本編では、タスクの投入先やスライスをカーネル内の BPF callback で決め、Rust の loader がロードと接続を担当した。
実行順を Rust のデータ構造で決めるには、BPF 側からユーザ空間へタスクを受け取り、選んだ CPU やスライスを BPF 側へ返す必要がある。

BPF 内では、使えるデータ構造と処理に制約がある。
複雑なキュー操作を記述しにくい場合は、タスクを選ぶ処理をユーザ空間へ移すことが選択肢になる。
`scx_rustland_core` は BPF とのタスクの受け渡しを抽象化し、この構成を支える。

公式の `scx_rustland` は、ユーザ空間で方針を実装するためのテンプレートである。
タスクを dequeue し、Rust のデータ構造で順序を決め、CPU とスライスを指定して dispatch できる。
